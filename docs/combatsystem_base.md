# 전투 시스템

## 0. 플레이어 가능 행동

플레이어가 취할 수 있는 행동은 다음 네 가지입니다.

- **움직임** (이동)
- **공격**
- **가드** (방어)
- **회피**
  
이후 모든 시스템(스태미나 회복 정지 조건, 콤보 버퍼 유지/초기화, 판정 우선순위 등)은 이 네 가지 행동을 기준으로 정의됩니다.


## 1. 체력 / 스태미나 시스템

### 1-1. 기본 구조
- 플레이어와 적 모두 체력(HP), 스태미나(SP) 보유. 최댓값 각각 100.
- 무기는 베기 / 찌르기 / 둔기 세 가지 데미지 값을 각각 가진다.

### 1-2. 데미지 계산 (단순화 버전)
확정 전까지는 아래 단순 수식으로 우선 구현합니다.

```
최종 데미지 = 무기의 해당 속성 데미지
            × 공격 종류 배율 (일반공격 1.0 / 강공격 1.5 / 콤보 피니셔 1.3 등)
            × (1 - 적의 해당 속성 방어구 저항률)
```

- 저항률은 0~1 사이 값이며, 방어구 부위(머리/몸통/팔/다리 등) 구분은 1차 구현에서는 생략하고 "적 1체당 단일 저항 세트"로 시작합니다.
- 부위별 판정, 크리티컬 등은 추후 확장 항목으로 남겨둡니다.

### 1-3. 데미지 우선순위 및 오버플로우
- 스태미나 > 0 인 동안은 데미지가 스태미나에 먼저 들어간다.
- **오버플로우는 전이됩니다.** 한 타격의 데미지가 남은 스태미나보다 크면, 초과분은 같은 타격 내에서 즉시 체력으로 넘어갑니다.

```
if (남은 스태미나 > 0):
    스태미나차감 = min(데미지, 남은스태미나)
    체력차감 = 데미지 - 스태미나차감      # 오버플로우, 같은 타격에서 즉시 적용
    스태미나 -= 스태미나차감
    체력 -= 체력차감
else:
    체력 -= 데미지
```

### 1-4. 스태미나 회복
- 최댓값 공식: `30 + 70 * (현재 체력 / 100)` — 유지.
- **회복량은 초당 상수값** (`SP_RegenPerSecond`, DataTable). 체력 비율에 연동하지 않고 고정 수치로 시작합니다.
- **회복 정지 조건**: 점프 / 달리기(스프린트) / 회피 / 공격 / 가드(방어 유지) 행동을 하면, 해당 행동 종료 후 `SP_RegenDelay`(N초, 상수) 동안 회복이 정지됩니다.
- **이동(걷기)은 회복을 막지 않습니다.**
- **최댓값 캡 하향 처리**: 체력이 줄어 스태미나 최댓값이 낮아지면, 현재 스태미나가 새 최댓값보다 클 경우 **즉시 새 최댓값으로 클램프**됩니다. (서서히 감소 X, 즉시 적용)

```
새캡 = 30 + 70 * (체력 / 100)
스태미나 = min(스태미나, 새캡)   # 체력이 깎일 때마다 매 프레임/매 이벤트 체크
```

## 2. 이동 시스템

### 2-1. 락온 스트레이프
- 락온한 적을 기준으로 좌우 입력 시 거리 유지 원형 이동.
- **반경, 각속도는 DataTable 상수**로 지정 (`LockOn_StrafeRadius`, `LockOn_AngularSpeed`). 무기 종류나 착용 장비(중갑 등)에 따라 다른 값을 매핑할 수 있도록 키를 무기/장비 ID로 잡아두는 걸 권장합니다.

### 2-2. 다수 적 포위 AI (슬롯 시스템)
- 락온 대상 주변 근접 허용 인원, 포위 각도, 판정 반경 모두 **DataTable 상수**로 지정.
  - `Surround_MaxCloseSlots` (락온 대상 포함 근접 허용 인원 수)
  - `Surround_CloseSlotRadius` (근접 슬롯 판정 반경)
  - `Surround_SideAngle` (포위 시 측면으로 벌어지는 각도)
- 슬롯 점유/해제 로직(락온 대상이 바뀌면 슬롯도 재계산 등)은 별도 AI 비헤이비어 문서에서 다루는 걸 권장합니다. 이 문서에서는 상수만 정의합니다.

## 3. 공격 방향 시스템

### 3-1. 공격 성공 시 다음 방향 자동 전환 (유지)

| 이번 공격 방향 | 다음 자동 방향 |
|---|---|
| 오른쪽 | 왼쪽 |
| 왼쪽 | 오른쪽 |
| 아래 | 오른쪽 |
| 위 | 왼쪽 |

### 3-2. 방어 성공 시 다음 공격 방향 자동 전환 (유지)

| 방어한 공격 방향 | 다음 공격 방향 |
|---|---|
| 오른쪽 | 왼쪽 |
| 왼쪽 | 위쪽 |
| 아래 | 오른쪽 |
| 위 | 오른쪽 |

### 3-3. 비대칭은 의도된 설계 — MasterStrike 난이도 차등

**확정**: 3-1/3-2 표의 비대칭은 의도된 것이며, MasterStrike 발생 조건의 난이도를 방향별로 차등화하기 위한 장치입니다.

- 자신이 **아래(Down) 또는 오른쪽(Right)** 방향으로 공격하는 경우 → 이 표의 자동 흐름을 그대로 따라가기만 해도(별도 마우스 조작 없이) MasterStrike 가능 상태로 자연스럽게 이어집니다. **"쉬운 방향"**.
- 자신이 **위(Up) 또는 왼쪽(Left)** 방향으로 공격하는 경우 → 자동 흐름만으로는 MasterStrike 조건이 맞춰지지 않으며, 플레이어가 **마우스를 능동적으로 움직여 방향을 재조정**해야만 MasterStrike 가능 상태가 됩니다. **"어려운 방향"**.


### 3-4. 적의 반격 조건
- 적 스태미나가 `Enemy_CounterStaminaThreshold`(%, DataTable 상수) 이상이고 Perfect Block 성공 시 → 막은 방향에서 즉시 반격.
- 이 상수 미만이면 즉시 반격하지 않음.

### 3-5. 콤보 지속 조건 (확정)
- **Perfect Block 당하면 콤보(입력 시퀀스)가 끊깁니다.**
- **일반 Block(퍼펙트 아님) 또는 공격이 적중하면 콤보가 유지됩니다.**

## 4. 콤보 시스템 — 커맨드 매칭 방식

### 4-1. 커맨드(입력 히스토리) 매칭 기반

 **격투 게임의 커맨드 인식 방식**입니다.

- 시스템은 플레이어가 성공적으로 낸 **최근 공격 방향들의 순서(입력 히스토리 버퍼)** 를 계속 추적합니다.
- 매 공격이 적중(또는 유효 판정)할 때마다, 히스토리 버퍼의 **끝부분이 등록된 콤보 패턴과 일치하는지** 검사합니다.
- 일치하면, 이번 공격은 일반 방향 공격이 아니라 **해당 콤보의 피니셔**로 대체되어 나갑니다.

**예시**: 플레이어가 "아래 → 아래"를 이미 입력한 상태에서, 세 번째 공격으로 "오른쪽"을 입력했다면 → 히스토리가 `[아래, 아래, 오른쪽]`이 되고, 이는 "폼멜 타격" 패턴과 일치하므로 세 번째 공격은 **일반 오른쪽 공격이 아니라 폼멜 타격**으로 발동합니다.

- 이 방식에서는 방향이 **자동 전환으로 나왔는지 수동 전환으로 나왔는지는 무관**합니다. 결과적으로 실현된 방향 시퀀스만 봅니다.


| 콤보명 | 패턴(순서) | 비고 |
|---|---|---|
| 기본 콤보 1 | 좌 → 우 → 좌 | 자동 전환만으로 발생 가능 |
| 기본 콤보 2 | 우 → 좌 → 우 | 자동 전환만으로 발생 가능 |
| 폼멜 타격 | 아래 → 아래 → 우 | 두 번째 "아래"는 수동 방향 재조정 필요 |

- 새로운 콤보 추가 시 이 사전에 패턴만 등록하면 되는 구조로 설계합니다 (DataTable 기반 `FCombatComboRow` 형태 권장: 패턴 배열 + 피니셔 몽타주 + 데미지 값).

### 4-3. 히스토리 버퍼 규칙
- 버퍼 최대 길이는 등록된 콤보 중 가장 긴 패턴 길이 기준으로 관리 (현재는 3).
- **버퍼 초기화(리셋) 조건**:
  - 적이 Perfect Block 성공 (3-5 확정 사항과 동일)
  - 콤보 타임아웃: 마지막 공격 이후 `Combo_BufferTimeout`(초, DataTable 상수 또는 AnimNotify) 동안 다음 공격이 없으면 초기화
- **버퍼 유지 조건**: 일반 Block 당하거나, 공격이 적중해도 버퍼는 계속 유지됩니다.

### 4-4. 콤보 타격 간 입력 유예
- 입력 유예 시간은 **DataTable 상수(`Combo_InputWindow`) 또는 공격 애니메이션의 AnimNotify**로 지정합니다. (몽타주별로 타이밍이 다를 수 있으므로 AnimNotify 방식을 권장)

### 4-5. 피니셔 데미지 구조 (MasterStrike와 동일 패턴으로 통일)

**확정**: 콤보 피니셔도 MasterStrike처럼 "기본 데미지 + 체력 우선 데미지" 이원 구조를 가집니다.

```
피니셔 총 데미지 = 기본 데미지(스태미나 우선 규칙 적용) + 체력 우선 데미지(무조건 체력에 적용)
```

- 각 콤보 패턴마다 "기본 데미지"와 "체력 우선 데미지" 값을 콤보 사전(4-2)에서 개별 지정합니다.

## 5. MasterStrike / PerfectBlock 판정 타이밍

### 5-1. 판정 구간 (3-3 규칙과 연동)
- 적 공격 모션 중 특정 지점부터 방어/MasterStrike 입력 가능 구간 시작.
- **3-3에서 정의한 "쉬운 방향(아래/오른쪽)"과 "어려운 방향(위/왼쪽)"에 따라 판정 조건이 분기**되어야 합니다:
  - 쉬운 방향: 자동 전환 흐름을 유지한 채 입력 시 MasterStrike 가능
  - 어려운 방향: 수동으로 방향을 재조정한 상태에서 입력해야 MasterStrike 가능

### 5-2. 실측 데이터 편차의 원인 — 인게임 슬로우모션

**확정**: v1에서 지적했던 C-A(방패 아이콘~피격) 값의 편차(0.75~0.984초)는 **인게임 슬로우 모션 효과 때문**입니다. 실제 판정 구간 길이 자체는 **무기별 고정값**입니다.

- 즉 "InGameTime 기준 판정 구간 길이"는 무기마다 고정 상수(`MasterStrike_WindowDuration_ByWeapon`, DataTable)로 정의하되, **실제 체감/측정되는 시간(WorldTime)은 슬로우모션 배율에 따라 달라질 수 있음**을 감안해서, 타이밍 판정 로직은 **InGameTime(또는 Time Dilation 보정된 시간) 기준**으로 계산해야 합니다.

```
타임라인 (예시, InGameTime 기준 — 무기별 상수)
0.0초   적 공격 시작
0.1초   방패 아이콘 등장 (판정 구간 시작) — 무기별 상수
0.5초   판정 구간 종료 — 무기별 상수
0.6초   MasterStrike 성공 시 몽타주 시작 (입력 시점과 무관)
0.8초   MasterStrike 실패 시 데미지 콜라이더 활성화 — 무기별 상수
```

### 5-3. 실패 시 분기 (확정)

```
0.5초 이후 ~ 콜라이더 활성화(0.8초) 이전 구간:
  └─ 플레이어가 공격 적중 시
        → 적의 공격은 완전히 캔슬됩니다 (클래시 아님, 적 공격 무효화)

0.5초 이후, 플레이어가 (퍼펙트 아닌) 일반 방어 시:
  └─ 그냥 맞는 것보다 적은 피해, 단 적은 콤보를 계속 이어갈 수 있음
```

### 5-4. MasterStrike 데미지 구조
- "기본 데미지 + 체력 우선 데미지" 이원 구조 확정 (4-5와 동일 패턴).
- 구체적 수치는 **DataTable 상수**(`MasterStrike_BaseDamage`, `MasterStrike_PriorityHealthDamage`)로 지정, 무기별로 다르게 매핑 가능하도록 설계.

### 5-5. PerfectBlock 이후 반격
- Perfect Block 성공 시 화면 중앙 아이콘 표시, 해당 방향으로 즉시 공격 가능.
- **유예시간, 확정 히트 여부 모두 DataTable 상수**로 지정:
  - `PerfectBlock_CounterWindow` (아이콘 유지/입력 유예 시간)
  - `PerfectBlock_GuaranteedHit` (bool — 확정 히트 여부. false면 일반 공격처럼 막히거나 회피당할 수 있음)

## 6. 이동/공격 중 공통 사항 정리
- 걷기(이동)는 스태미나 회복을 막지 않음 (1-4).
- 점프/스프린트/회피/공격/가드는 스태미나 회복을 지연시킴 (1-4).

## 7. DataTable 상수 목록 (설계 확정, 수치 미정)

구현 시 코드에 하드코딩하지 않고 아래 항목들을 DataTable(또는 CurveTable)로 노출해야 합니다.

**스태미나 / 체력**
- `SP_RegenPerSecond`
- `SP_RegenDelay` (점프/스프린트/회피/공격/가드 이후 정지 시간)

**이동**
- `LockOn_StrafeRadius`
- `LockOn_AngularSpeed`
- `Surround_MaxCloseSlots`
- `Surround_CloseSlotRadius`
- `Surround_SideAngle`

**전투 판정**
- `Enemy_CounterStaminaThreshold` (%)
- `Combo_BufferTimeout`
- `Combo_InputWindow` (또는 AnimNotify로 대체)

**콤보 피니셔 (콤보별 개별 값)**
- `Combo_BaseDamage`
- `Combo_PriorityHealthDamage`

**MasterStrike (무기별 개별 값)**
- `MasterStrike_WindowStart` / `MasterStrike_WindowEnd`
- `MasterStrike_ColliderActivation`
- `MasterStrike_BaseDamage`
- `MasterStrike_PriorityHealthDamage`

**PerfectBlock**
- `PerfectBlock_CounterWindow`
- `PerfectBlock_GuaranteedHit` (bool)

**데미지 계산**
- 무기별 베기/찌르기/둔기 원본 데미지
- 적별 베기/찌르기/둔기 저항률
- 공격 종류별 배율(일반/강공격/콤보 피니셔)
